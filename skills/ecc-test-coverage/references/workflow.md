# Shared development workflow

Use the relevant skills installed alongside this one for development tasks.

## Personal requirements

- Write clean code without unnecessary source comments.
- Keep newly authored source files at or below 150 lines.
- Follow the current user's RTK and shell instructions; do not assume a fixed home path.
- After verified repository changes, use the installed auto-commit-task skill.
- Preserve unrelated changes, stage only task changes, and report the commit.
- Push or issue Jira Smart Commit commands only with explicit authorization.
- Explicit user instructions and project requirements take precedence over examples.

## Development workflow

- Plan complex work before implementation and keep changes focused.
- Use architecture, backend, frontend, database, and coding standards skills as relevant.
- Prefer small functions, cohesive modules, validated inputs, and explicit errors.
- Use meaningful regression tests and the project's own checks.
- Review authentication, authorization, secrets, and sensitive data when relevant.
- Review the final diff and address defects before committing.
- Treat specialist profiles as guidance and use available host tools.
- Delegate only when the host, user, and current instructions allow it.
- Keep the user's selected model and permission settings.
- Treat project-guidelines-example as a template rather than project architecture.
- Claude lifecycle hooks run only in a configured Claude Code environment.

Read this skill's bundled specialist or command reference for its actual workflow.
Related development patterns are available through the other installed skills.
